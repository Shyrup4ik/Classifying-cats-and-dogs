# Лапа — классификация кошек и собак

Готовое приложение на основе [исходного проекта](https://github.com/Shyrup4ik/Classifying-cats-and-dogs): FastAPI + PyTorch на CPU, адаптивный frontend и Nginx. Обученные веса уже скопированы из `/Users/yuri/Downloads/cat_dog_fixed.pt` в `models/`. Исходные ноутбуки сохранены, описание обучения — в [README_MODEL.md](README_MODEL.md).

## Запуск

Откройте Docker Desktop и дождитесь запуска. В первом терминале:

```sh
cd /Users/yuri/Documents/projects_for_reu/Backend-Classifying-cats-and-dogs
docker compose up --build
```

Откройте [http://localhost:8080](http://localhost:8080). Первый запуск скачивает CPU-библиотеки PyTorch и Docker-образы. При следующих запусках используется кэш. Backend запускается с реальными весами; при отсутствующем или несовместимом файле он завершится с ошибкой, не выдавая случайные предсказания.

Команды выполняйте в корне указанной папки, где находится `docker-compose.yml`. Если порт 8080 занят, остановите другое приложение или укажите `APP_PORT=8081 docker compose up --build` и используйте 8081 в адресе туннеля.

## Доступ через интернет

Во втором терминале:

```sh
cloudflared tunnel --protocol http2 --url http://localhost:8080
```

Скопируйте HTTPS-ссылку с окончанием `trycloudflare.com`. Пока оба процесса работают и компьютер включён, ссылка доступна извне. При следующем запуске она может измениться. Для остановки нажмите `Ctrl+C` в обоих терминалах. Для удаления остановленных контейнеров: `docker compose down`.

## Использование

1. Выберите или перетащите одно фото, либо нажмите на один из двух примеров.
2. Нажмите «Распознать фото».
3. Получите класс и вероятности кошки и собаки. Можно сбросить результат и выбрать другое фото.

Поддерживаются JPEG, PNG и WebP до 10 МБ и 20 мегапикселей. Фото обрабатываются в памяти и не сохраняются на сервере. Интерфейс показывает ошибки файла, отключения сервера, занятости модели и тайм-аута. При близких вероятностях предлагает более чёткое фото. Нейросеть всегда выбирает между двумя классами, даже если на снимке другой объект; проценты не гарантируют правильность ответа.

## API

- `GET /api/health` — готовность модели, устройство, идентификатор весов и лимиты.
- `POST /api/predict` — `multipart/form-data`, поле `file`.
- `GET /api/openapi.json` — спецификация OpenAPI.

```sh
curl -F 'file=@/полный/путь/photo.jpg' http://localhost:8080/api/predict
```

Пример структуры ответа:

```json
{
  "label": "cat",
  "label_ru": "Кошка",
  "confidence": 0.94,
  "probabilities": {"cat": 0.94, "dog": 0.06},
  "image": {"width": 800, "height": 600},
  "inference_ms": 24.5,
  "model": "ResNet18",
  "weights_id": "идентификатор"
}
```

Значения приведены только как пример формата. Ошибки возвращаются JSON-объектом с полем `detail` и кодом 400, 413, 422, 429 или 500.

## Модель

Архитектура и обработка повторяют `Run_ResNet18.ipynb`: `conv1.stride = (1, 1)`, `maxpool = Identity`, два выхода `fc`; RGB → Resize(32×32) → ToTensor → Normalize(mean=[0.485, 0.456, 0.406], std=[0.229, 0.224, 0.225]). Порядок классов — `cat`, `dog`. Случайного отражения нет; фото с EXIF-поворотом предварительно приводятся к правильной ориентации. Модель загружается один раз при старте через `weights_only=True`, работает в `eval()` и `inference_mode()`, ничего не скачивает при предсказании.

Веса подключаются к контейнеру только для чтения и игнорируются Git. Для замены весов положите совместимый `state_dict` в `models/cat_dog_fixed.pt` и выполните `docker compose restart backend`. Интернет нужен для первой сборки и публичного туннеля, локальное распознавание работает без внешнего API.

## Проверка

```sh
docker compose --profile test run --build --rm tests
```

Тесты используют реальные веса: сверяют результат с исходным ноутбуком, проверяют примеры кошки и собаки, повторяемость, поддерживаемые форматы, EXIF, повреждённые и слишком большие файлы и занятость модели.
